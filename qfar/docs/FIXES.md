# Change log: v1 (ZIP) → v2

Each item from the review is listed with what changed and where to verify it.
"Kept" means the ZIP behaviour was correct and was deliberately left alone.

| # | Item | Resolution | Code / evidence |
|---|---|---|---|
| 1 | Repayment dataset | Data stay **synthetic**, and the project is labelled a synthetic-data simulation study everywhere. Added a stratified 60/20/20 **train/validation/test** split; CV runs on train only; the shortlist is chosen on validation; one test evaluation. Added a real-data loader `load_labelled_csv` that validates the schema. Protected attributes are excluded from the model (asserted). | `data.py`, `pd_model.py`, `scripts/01_train_pd.py`, `docs/DATA_CARD.md`, `test_split_is_disjoint_and_stratified`, `test_labelled_csv_loader` |
| 2 | Financial score | Cohort min-max replaced by fixed bounds: $F=(\mu+LGD)/(r+LGD)$. With constant $r$ and LGD this equals $p_i$; this is documented and tested. Named a *normalised expected-return score*, not profit. | `scoring.financial_score`, `test_score_ranges_and_F_definition` |
| 3 | Need score | $PCI$ normalised on a fixed range [1,000, 25,000]; dependents on a fixed max of 6. Weights 0.5/0.3/0.2 kept as provisional. | `scoring.need_score`, config `normalisation` |
| 4 | Social score | **Option A** implemented: four financial-exclusion indicators (simulated in the synthetic data and declared as such). Automatic fallback to **Option B "Social Priority Score"** if a dataset lacks them. Nothing is fabricated for real data. | `scoring.social_score`, `test_social_score_falls_back_to_priority_without_indicators` |
| 5 | Composite utility | One declared baseline (1/3, 1/3, 1/3) used everywhere; simplex check enforced. Correlations between scores are measured and reported. | `scoring.compute_scores`, `results/01_pd_model/score_feature_spearman.csv` |
| 6 | Budget via slack | Kept the ZIP slack encoding. Added conservative integer rounding (loans rounded up, budget rounded down). | `qubo.budget_units`, `test_slack_represents_exactly_0_to_B` (B = 1..299) |
| 7 | Budget penalty | $\lambda_B = 1.1\sum_i\max(U_i,0) + 10^{-3}$. Proof in FORMULATION §3.2. Non-PSD $\Gamma$ is rejected. Tested exhaustively, by sampling up to N = 80, across 5 budget fractions, and with a negative control. | `qubo.py`, `test_penalty_bound_*`, `test_feasibility_across_budgets`, `test_too_small_penalty_can_break_feasibility` |
| 8 | Fairness | **Approach A (soft)** in the QUBO, described as soft everywhere. A real hard constraint $\lvert d\rvert\le\epsilon$ exists only in the MILP solvers. Signed DPD and **directional** $DIR_{A/B}$, $DIR_{B/A}$ are reported. | `metrics.fairness_metrics`, `solvers.solve_milp(fair_eps=)` |
| 9 | Financial tail risk | Gaussian-copula default scenarios, $\mathcal L_s(x)$, and Rockafellar–Uryasev CVaR. Both an **evaluation metric** for every solver and **inside the objective** of P2 through an exact MILP encoding (tested against enumeration). The variance term uses the same default model. | `risk.py`, `solvers.solve_milp(tail=)`, `test_cvar_*`, `test_cvar_milp_equals_enumeration_P2` |
| 10 | QUBO objective | P1 = utility + variance + soft fairness + slack budget, documented as *variance-aware* and not called CVaR. P2 (with CVaR) is solved classically. The quantum solvers handle P1 only, and this is stated. | `docs/FORMULATION.md §5` |
| 11 | MILP comparison | New `milp_linearised` solves the **same** P1 as enumeration and the QUBO (McCormick products, exact). `milp_linearised_cvar` solves P2. The old MILP is kept as `milp_hard_fair_utility` and labelled a **separate problem**. | `solvers.solve_milp`, `test_linearised_milp_equals_enumeration_P1`, `test_hard_fair_milp_solves_its_stated_problem` |
| 12 | Greedy | Renamed `greedy_utility_per_cost` ("Greedy Utility-per-Cost Baseline"). Documented as ignoring risk and fairness. | `solvers.solve_greedy` |
| 13 | QUBO → Ising | Mapping kept. Equivalence tested on 300 random bitstrings for N ∈ {3, 5, 8, 12, 20}, plus a direct check of the $h$ and $J$ formulas. | `test_ising_*` |
| 14 | QAOA interpretation | Quantum CVaR (lower tail of energies) is distinguished from financial CVaR (upper tail of losses). Runs are labelled **ideal statevector simulation**. Reported: depth, qubits, shots, evaluations, $P_{opt}$, $P_{feasible}$, objective. The selection rule (lowest-energy sample) is explicit, and the most frequent sample is also reported. | `quantum.py`, `results/03_allocation/quantum_summary.csv` |
| 15 | QAOA/VQE evaluation | 30 cohorts. $P_{opt}$ and $P_{feasible}$ are given exact and from shots, next to their uniform-random baselines. Weak results are reported as they are (see README). | `scripts/03_allocation_experiment.py` |
| 16 | Weight sensitivity | 30 cohorts × 66 simplex points; all 11 requested metrics including CVaR, Jaccard and Kendall τ. | `scripts/02_weight_ablation.py` |
| 17 | Component ablation | E1–E7 plus penalty ablation (utility only, +variance, +fairness, both, fairness ×5, +CVaR at 4 values of $\lambda_R$), on identical cohorts and scenarios, solved exactly. | `scripts/04_component_ablation.py` |
| 18 | Allocation experiment | 30 cohorts. Every requested metric, reported as mean and SD (ddof = 1). Added realised loss computed from held-out labels. | `scripts/03_allocation_experiment.py`, `metrics.mean_sd` |
| 19 | Group definitions | Groups are named only "Group A" and "Group B" and declared synthetic, with their assumed characteristics tabulated. A column-role table separates the fairness group, PD features, Need inputs and Inclusion inputs. | `data.py` docstring, `docs/DATA_CARD.md` |
| 20 | Normalisation and reproducibility | No cohort-dependent normalisation remains (tested). Every run writes `manifest.json` with config, seeds, package versions and git commit. Saved: split IDs, cohort IDs, model. One instance per cohort is shared by all solvers. | `config.write_manifest`, `test_scores_are_independent_of_cohort_composition`, `test_reproducibility_with_fixed_seeds` |
| 21 | Structure and tests | ZIP layout kept. Added `config.py`, `risk.py`, `quantum.py` (statevector code moved out of `solvers.py`), `scripts/04_component_ablation.py`, pytest suite, CI, `pyproject.toml`. | `tests/` (all 10 requested test categories) |
| 22 | Final formulation | Written in `docs/FORMULATION.md`, with each part marked *implemented and tested* or *not implemented* (no QUBO encoding of CVaR). | |
| 23 | Order | Followed in that order. | |
